Udyam Setu: solution architecture

The model talks, the rule engine decides, the registries confirm. Each box is marked Built (running in the prototype repo, covered by tests), Simulated (working in the prototype against mock data or a stub) or Planned (production design, not built). Prototype stack: FastAPI, a mobile web app (PWA), SQLite, Tesseract + OpenCV, scikit-learn, Claude via an API behind a validation layer. Production target: WhatsApp Cloud API, Postgres, Bhashini ASR/TTS, all in an India region.

EXPERIENCE SERVICES
BUILTSaathi advisor (GenAI)Claude understands free text in any Indian language and explains the bundle in the owner's language. Every output is validated: values outside the allowed options are dropped; an explanation whose prices differ from the quote is discarded. PII redacted before the model. Offline parser + reviewed templates as fallback.
BUILTBundle rule engineDeterministic: city tier, min employees/sites, requires_gstin, requires_one_of, price bands, install days. Owns every product, price and eligibility decision.
BUILTQuote & checkoutLive price with add-on toggles, setup fee, contract term; dependencies re-checked on each toggle. UPI autopay mandate planned.
BUILTLanguage layerReviewed phrase bank (3 languages); Bhashini ASR/TTS for 10 languages planned
BUILTPropensity scorerLogistic regression on 13 lead fields, 5-fold CV AUC 0.71; routes stalled leads

Main flow: owner → app → Saathi (needs profile) → rule engine (eligible bundle and price) → quote → consent → KYC (lookup first, documents only if needed) → eSign → order → tracker.
Side flows: stalled or high-propensity leads → partner back office · every personal-data touch → consent ledger + masked audit · order events → WhatsApp notifier.
